# Additional BMFF Hash Exclusions

`builder.bmff_hash_extra_exclusions` adds exclusion descriptors to BMFF hash
assertions generated by the SDK. It defaults to an empty list. Required and
default exclusions remain in place; exact duplicates are not added twice.
The JSON/TOML settings travel through the existing `Context`, including from
C and Python callers.

```json
{
  "builder": {
    "bmff_hash_extra_exclusions": [{"xpath": "/sidx"}]
  }
}
```

Descriptors support `xpath`, `length`, `data`, `subset`, `version`, `flags`,
and `exact`. This setting accepts absolute paths composed of four-character
box names, without wildcards or occurrence indices. Settings loading checks
descriptor structure and subset arithmetic, not the semantic safety of
excluding the selected content. For example, excluding essential media or
decoding metadata can undermine the intended hard binding.

The setting applies to automatic file hashing, `mdat` Merkle hashing,
fragmented signing, and BMFF placeholders. One assertion list covers
initialization and media hashes: `/sidx` excludes every matching root-level
index, including one in the initialization region. This proposal does not
add automatic single-file fragment Merkle signing or rendition-ladder support.

Pre-existing assertions must already contain every requested exact descriptor.
This check also applies to embeddable signing and assertions reused across
renditions. The SDK does not retrofit exclusions onto a previously computed
hash. Generated placeholders already contain the requested descriptors.
BMFF update manifests reject nonempty requests; other asset formats are not
affected. These settings checks occur before signing or writing media outputs.

## Index Integrity

Excluding `/sidx` does not change the file's layout or its sample timestamps.
It makes the index unauthenticated while retaining the default coverage of
`moov`, `moof`, `mdat`, and retained root-box offsets. Altered samples or
authenticated timing metadata still fail their bindings.

A player can use `sidx` for both seeking and ordinary fetch scheduling. An
attacker controlling an excluded index may cause wrong range requests, stalls,
gap recovery, skipped content, or early stopping, depending on the consumer.
Index changes alone do not rewrite authenticated sample timing or establish
arbitrary seamless retiming. Authentic fragment membership is not proof of
correct requested-time selection, ordering, or presentation completeness.

C2PA 2.4 permits additional BMFF exclusions and specifies the informational
`assertion.bmffHash.additionalExclusionsPresent` diagnostic. It does not
specifically endorse excluding `sidx`. The caller must assess the asset and
consumer profile rather than treating successful hashing as a semantic
compliance certification.
